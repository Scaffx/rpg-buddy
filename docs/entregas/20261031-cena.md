# Cena da aventura durante recuperação — 31/10/2026

## Diagnóstico e limite da evidência

[Certo] A base compartilhada começou em `9a00224ec1d79cfeed87aca5d5c85cf95a193402`; o `main` publicado identificado pela coordenação é `8955e80`. Em `8955e80:src/components/AutoAdventure.tsx`, `const recovering = Boolean(catchup?.pending)` substitui `AdventureScene` pelo aviso “Sincronizando suas lutas anteriores” em qualquer lote pendente, independentemente de existir uma batalha atual com `started_at <= serverTime < ends_at`. Isso explica a ausência da cena na captura de etapa 33 enquanto a resposta indicava recuperação; o código da captura não prova por si só que o servidor enviou uma batalha viva naquele lote.

[Certo] BUG-47 documenta o caso anterior de 24 batalhas e resumo com `battles=0` antes da correção PR70. A captura atual indica 672 combates recuperados em lotes de 42. A condição de ocultação em `8955e80` é suficiente para o sintoma visual sem atribuir a este caso a causa do BUG-47. O rascunho já tinha a guarda temporal para uma batalha viva; este trabalho a preservou e impediu que uma linha `fighting` expirada seja exibida como luta viva após o fim de `pending`. Quando não há luta viva, a cena permanece em `exploring`, com HP desconhecido e sem ação projetada, acompanhada por aviso de recuperação se `pending=true`.

[Certo] A UI de “Confrontos recentes” e o cartão “Último resultado” foram retirados. O resumo agregado de `catchup` permanece como recibo de recuperação. `data.encounters` ainda chega na própria resposta de `sync_auto_adventure` e ainda serve ao aviso de recuo em `holding`; não há query de leitura de histórico separada neste componente ou em `useAutoAdventure` a desativar. Tabelas e recibos internos não foram modificados.

[Certo] `AdventureJourneyPanel` foi inserido depois da área da cena com `data.stage` do snapshot; o módulo da jornada consulta sua própria etapa confirmada e mostra carregamento/erro em seu cartão, sem esconder `AdventureScene`.

## Hunk portátil para `main`

[Certo] O hotfix mínimo para a ocultação da cena no `main` não exige SQL v4: manter o relógio ativo durante `pending`, separar `battle` vivo de snapshot histórico e renderizar a cena sempre. No componente de `8955e80`, os trechos locais equivalentes são:

```tsx
const serverTime = useServerClock(data?.server_now, dataUpdatedAt, currentBattle?.status === 'fighting');
const startedAt = Date.parse(currentBattle?.started_at ?? '');
const endsAt = Date.parse(currentBattle?.ends_at ?? '');
const liveBattle = currentBattle?.status === 'fighting' && startedAt <= serverTime && endsAt > serverTime;
const currentBattleForScene = currentBattle?.status === 'fighting' &&
  Number.isFinite(startedAt) && Number.isFinite(endsAt) && !liveBattle ? null : currentBattle;
const recovering = Boolean(catchup?.pending && !liveBattle);
const battle = recovering ? null : catchup?.pending ? currentBattleForScene : displayedDefeat ?? currentBattleForScene ?? null;
// projectAdventureSceneFrame(null, serverTime, 'exploring') no rascunho v4;
// no main, o frame legado deve manter heroHp/enemyHp nulos quando battle === null.
```

[Certo] Na JSX do `main`, renderizar `<AdventureScene ... />` independentemente de `recovering` e colocar o aviso `Recuperando combates · Aguardando próxima luta confirmada` abaixo da cena quando `recovering=true`; o controle de pausa deve continuar habilitado para a animação exploratória. No port, substituir a declaração antiga de `serverTime` pelo primeiro trecho acima, sem duplicá-la. A versão publicada usa assinatura diferente de `useServerClock`; o trecho acima é para ela. O diff completo deste rascunho inclui contrato/parser/cena de horda e não é um patch seguro para copiar inteiro ao `main`.

## Verificação

[Certo] `npx vitest run src/test/AutoAdventure`: 13 arquivos e 67/67 testes locais passaram após a integração. O teste legado de horda recebeu um mock do painel de jornada, conforme ampliação pontual de ownership pela coordenação; ele continua exercitando a cena real. Os testes montados cobrem `catchup.pending=true` com batalha válida, HP e eventos futuros ocultos; batalha ausente ou expirada com cena `exploring`, HP desconhecido, aviso separado e pausa; `pending=false` com snapshot expirado; troca de conta; e ausência da lista de histórico. A fixture de batalha viva foi ancorada 1 s antes de `server_now` para evitar uma janela futura artificial. `npm run build` e ESLint direcionado terminaram com saída 0 após a integração. Esta evidência usa fixtures e DOM local; não demonstra resposta autenticada da RPC nem comportamento no navegador publicado.

[Incerto/a] Não foi observado um payload autenticado da captura com `battle.id`, `started_at`, `ends_at` e `server_now`; portanto, permanece aberta a possibilidade de o servidor não fornecer batalha atual em parte dos lotes. Nesse caso, a cena exploratória e o aviso de recuperação são apenas apresentação do estado desconhecido; o cliente não deve inventar luta, eventos, HP ou recompensas para preencher a espera.
